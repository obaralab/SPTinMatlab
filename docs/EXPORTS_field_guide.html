SPT Pipeline Field Guide

Every file the three tools write, what each field means, and a runnable snippet for each one. Field names, types and ranges below were read off a real project (CysLig, 93 cells, 464 contact sites) rather than transcribed from the code.

  • 3 tools
  • 34 files documented

  • 1 units exception

1 · Where files land

A project is one folder. The tools write into three places inside it, and never outside.

<project>/ experiment_details.mat the manifest: one row per cell, and where conditions are assigned spt/ the movies (input) er_seg/ mito_seg/ the organelle segmentations (input) tracks/ TOOL 1 — six files per cell <base>_spots.csv every detection <base>_spots_filtered.csv same rows, tracks renumbered <base>_spots_curated.csv after hand curation <base>_track_metrics.csv one row per track <base>_filter_log.csv why each track was kept or dropped <base>_settings.txt the run, in full analysis/ TOOLS 2 & 3 — one set per project <Name>.mat the build (TrackStruct) active_trackstruct.txt which build is current cs_calib.mat pixel size, frame interval, density bin track_exclusions.csv tracks rejected by hand csIDs/<base>_CSsites.txt the picks CS_footprints.mat site outlines (editable) CS_tessellation.mat the diffusion map CSW_final.mat the mapped sites — the central record cs_window_metrics.csv one row per site cs_window_dwell.mat / .csv visits cs_window_track_labels.csv one row per track at a site cs_engage.mat engagement classification cs_engage_sites.csv one row per site cs_engage_tracks.csv one row per track at a site CS_trackedits.mat tracks excluded from one site exports/<name>/advisor_format/<condition>/ the handoff (§6)

Files are additive. Nothing here overwrites a cell's raw data, and every stage can be re-run from the stage before it.

2 · Conventions that hold everywhere

Units

QuantityUnitWhere
position, distance, sizeµmeverywhere, with one exception below
refboundary in the advisor exportnm, relative to refCenter§6 — the one place µm is not the unit
areaµm² in this pipeline, nm² in the advisor spreadsheets§5, §6
timeframes, converted to seconds only at the endeverywhere
the refiner's ellipsepixels of 3 nm, pixel 400 = the pick§6
Seconds are derived, not measured

These TIFFs carry one nominal finterval for the whole stack and no per-page timestamps. Every second in every file here is a frame number multiplied by that one interval. Frame numbers are exact; seconds accumulate the interval's error, which is why the pipeline indexes by frame and converts once, at the end. A column named T_s is FRAME × dt and nothing more.

Indices

  • Frames are 0-based in every CSV and in matrix(:,:,1). Frame 0 is the first.
  • Track columns are 1-based, because they are MATLAB columns. trackCol, tracks and trackIDs all mean "column of matrix".
  • TRACK_ID in a CSV is 0-based and is not the same number as trackCol.
  • cellIndex is 1-based and indexes the build array.
  • siteUID is 1-based and unique across the whole project; csID is only unique within a cell.

The matrix idiom

A cell's tracks live in one [localization × track × 3] array. Column j is one track, padded with NaN below its end. Page 1 is the frame number, page 2 is x, page 3 is y. Every …LocIDs field is a set of linear indices into one page, so the same index reaches all three pages by adding the page stride.

C1the matrix idiom
T = Tracks(1);
frame = T.matrix(:,:,1);            % 0-based frame; NaN below a track's end
x     = T.matrix(:,:,2);            % um
y     = T.matrix(:,:,3);            % um

j  = 5;                             % one track = one column
ok = isfinite(x(:,j));              % exactly T.lengths(j) of them
fprintf('track %d: %d localizations, frames %d..%d\n', j, T.lengths(j), ...
        frame(find(ok,1), j), frame(find(ok,1,'last'), j));

% a set of linear indices reaches all three pages
n   = numel(frame);
ids = find(isfinite(x));                       % or any ...LocIDs field
got = [frame(ids), x(ids), y(ids)];            % same rows, three columns
A gap is not a missing row

Rows within a track are consecutive localizations, not consecutive frames. A tracking gap shows up as a jump in matrix(:,:,1) with no row in between. Use the frame page whenever you need elapsed time; counting rows undercounts it.

3 · Tool 1 — detection and tracking

Six files per cell in tracks/, all keyed to <base>, the movie's stem.

<base>_spots.csv

Every detection the run made, one row each, in frame order. 410,125 rows for the reference cell. Two siblings carry the same 14 columns: _spots_filtered.csv after the track-length and quality filter, and _spots_curated.csv after hand curation. All three have the same row count — filtering renumbers TRACK_ID and blanks the rows it drops, it does not delete them.

The distance columns are signed

MITO_DIST_UM runs from about −1.8 to +15.7 µm on the reference cell. A negative value means the localization sits inside the segmented organelle. Thresholding with abs() merges inside and outside and is almost never what you want; compare against 0 or against a signed cut-off.

        numel(unique(S.TRACK_ID(~isnan(S.TRACK_ID)))));

id = 140;                                  % a TRACK_ID, 0-based
r  = S(S.TRACK_ID == id, :);
r  = sortrows(r, 'FRAME');
fprintf('track %d: %d spots, frames %d..%d, %d gap frames\n', id, height(r), ...
        r.FRAME(1), r.FRAME(end), (r.FRAME(end)-r.FRAME(1)+1) - height(r));

inside = r.MITO_DIST_UM < 0;               % signed: negative is inside the mask

allSpots vs matrix

matrix holds only linked localizations. allSpots holds every detection, linked or not. Density, enrichment and background all read allSpots; anything about motion reads matrix. Using the wrong one changes a density by the fraction of detections that were never tracked — 98.6% of them on the reference cell.

The outline has a floor, and it is σ

An automatic outline is a contour of a density smoothed at outlineSigmaNm. The half-max contour of a single point at σ = 100 nm is already a circle of radius σ·√(2·ln2) = 118 nm (0.044 µm²). No automatic outline can be smaller, however tight the localizations are.

On the reference project, 36% of the 464 footprints sit within 25% of that floor and 10% are at or below it. Where a site's localizations are tighter than σ the outline is set by the smoothing rather than by the data — one site wraps a 63 nm knot of 351 localizations in a 165 nm circle. Lower outlineSigmaNm in the Refine tab, or draw those sites freehand.

F1which outlines are set by σ rather than by the data
L = load(fullfile(ana,'CS_footprints.mat'));
F = L.CSfoot(~[L.CSfoot.deleted]);
floorR = 1.1774 * L.outlineSigmaNm / 1000;              % um, the smallest possible radius

r = sqrt([F.areaUm2] / pi);
fprintf('sigma %g nm -> floor %.0f nm; %d of %d sites within 25%% of it\n', ...
        L.outlineSigmaNm, floorR*1000, nnz(r < floorR*1.25), numel(F));

atFloor = find(r < floorR*1.25 & contains(string({F.mode}), 'halfmax'));
for k = atFloor(1:min(5,end))
    fprintf('  %s csID %d: r = %.0f nm (%s)\n', F(k).file, F(k).csID, r(k)*1000, F(k).mode);
end

Dwell and engagement

Three .mat files and four CSVs. The CSVs are flat views of the same records, written so the numbers can leave MATLAB without a loader.

cs_window_track_labels.csv gives each track at each site one of four labels:

LabelMeans
RESIDENTpresent at the start and the end — both ends censored
ENTERSarrives during the window and is still there at the end
EXITSpresent at the start, leaves
ENTERS+EXITSa complete visit, both ends observed
Censoring is the whole game for dwell times

Only ENTERS+EXITS visits have a dwell time you observed in full. Taking the mean of allDwell across every label mixes complete visits with truncated ones and biases the answer downward. Either restrict to complete visits, or use the censoring-aware estimator τ = total observed time ÷ completed visits, which perSite.kout already is (as a rate).

The condition column can be blank here

Conditions flow manifest → cs_condition_apply → CSW_final.mat → engagement, so re-run the classifier after assigning conditions, or join on siteUID as in R1 below.

6 · The advisor format export

Written to analysis/exports/<name>/advisor_format/<condition>/, one folder per condition. It reproduces the published VAPB ContactSites layout exactly — same file names, same variables, same fields in the same order, same spreadsheet columns — so the original lab scripts run on it unchanged.

advisor_format/Baseline/ CS_final_v3.mat CS — one entry per contact site Baseline_Tracks_finalv3.mat Tracks — one entry per cell Baseline_EC.mat EC — enrichment counts per cell BindingInfo.mat BindingInfo — empty: this pipeline has no hand annotation CS_details_v2.xlsx one row per site, 22 columns Baseline-CSstats.xlsx mito / other / total per cell Baseline-EnrichmentCoefficients.xlsx two sheets Baseline-BindingTable.xlsx present, empty imaging_settings.csv this data's own calibration, one row per cell README_advisor_format.txt what is filled, what is empty, what to change in the old scripts open_advisor_format.m base MATLAB, loads everything block by block
refboundary is in nanometres here

This is the one place the pipeline's µm convention does not hold, because the original CS_refiner_v2_wacom.m stored it that way. In this export:

  • refboundary — nm, relative to refCenter
  • refCenter, boundaries, CSmatrix x/y — µm
  • Area in the spreadsheets — nm² (median 128,000 here; 89,000 in the VAPB set)
  • EllipseFit — refiner pixels of 3 nm, with pixel 400 at the pick

Plotting refboundary straight onto a µm axis draws it 1000× too large. Always refboundary/1000 + refCenter.

    e = EC(c);
    MCSprob = sum(e.MCSsteps) / e.TotalSteps;      % share of the cell's localizations in mito sites
    OCSprob = sum(e.OCSsteps) / e.TotalSteps;      % share in other sites
    coeff = MCSprob / OCSprob;
    if OCSprob == 0, coeff = NaN; end              % left blank in the published sheet
    fprintf('cell %d: %d mito / %d other sites, MitoEnrichCoeff %.3g\n', ...
            e.cellIndex, e.NumMCSs, e.NumOCSs, coeff);
end
