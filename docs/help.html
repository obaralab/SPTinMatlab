SPTinMatlab — Help & Pipeline Guide

Single-particle tracking of an ER membrane protein at ER–mitochondria contact sites, from raw movies to per-site residence times. This guide explains every stage, the maths behind detection, and where to read the numbers.

New here? Read Overview → Quick start, then dip into the deep-dive sections when a control puzzles you. Every deep dive has a concrete worked example with real numbers from the WithER test cell.

Overview & data flow

The workflow is split into three focused apps. They couple through files only — each writes what the next reads, so you can stop, inspect, and resume at any stage.

SPT movie + ER seg + mito seg→ Tool 1 · Track→ _tracks_filtered.xml + _spots_filtered.csv→ Tool 2 · Curate & Build→ analysis/<name>.mat (active build)→ Tool 3 · Analyze→ contact sites · dwell · diffusion

Quick start

  1. Track (run_track): point the three folder pickers at spt/, er_seg/, mito_seg/ → Scan. On the Detect tab set the top-percentile (default 6 %); on the Track & filter tab set link/gap distances and pick a Linking mode from the dropdown (Euclidean · ER-penalty · ER-geodesic); run, filter (min length 50), export.
  2. Curate & Build (run_curate): import the curated tracks, type a Name for this build, then ▶ Build + QC (this is the slow MSD step — done once). QC individual tracks.
  3. Analyze (run_analyze): set the project folder — it opens the active build; on Contact sites pick a cell → Detect all → Save; on Refine tidy the boundaries; on Sites run the mapper; on Dwell compute residence times.

1 · Track

spt_app re-implements the paper's ERAware tracking in MATLAB. Tabs, in order:

  • Match files — three folders → regex key matching → a found/not-found table. SPT alone suffices; ER enables ER-aware linking; mito enables per-spot mito distance.
  • Detect — per-cell spot detection with a live preview. Two threshold modes: top % (keep the brightest N % of DoG responses, default 6) or Quality ≥ (an absolute cut). The percentile actually used is recorded per cell.
  • Track & filter — TrackMate-style LAP linking: link distance, max-gap distance, max-gap frames, and a Linking mode dropdown with three choices, softest to strictest:
    • Euclidean — distance only; the ER masks are ignored.
    • ER-penalty (default) — soft. The cost becomes dist·(1+λ·off-ER-frac) (λ=3, editable): an off-ER link costs more, but nothing is refused, so every detection can still end up in a track.
    • ER-geodesic — strict. A detection that does not sit on its own frame's ER is excluded from tracking entirely; the surviving links are costed by the shortest path through the ER, so a partner that cannot be reached without leaving the ER is forbidden. λ is unused in this mode.
    Both ER modes dilate the ER mask by 1 px to tolerate registration slack, and a frame whose ER mask is missing is treated as forbid, never as "no constraint". Detections that geodesic excludes are not thrown away — they stay in the spots CSV with a blank TRACK_ID. A methods comparison (⚖ Compare methods) lists the places the three methods link a spot differently and plays the one you pick as three side-by-side videos — one per method — over the real frames, so you can see what each method did rather than reading three overlaid markers. Panels are labelled when ER-penalty is identical to Euclidean, or when geodesic excluded the spot for being off the ER. Save video… writes it as an MP4. The same tab then filters the result by min track length (default 50) and min displacement — with a length histogram and a kept-vs-removed map — and exports the _tracks_filtered.xml + _spots_filtered.csv pair Tool 2 reads, for one cell or every tracked cell.
  • Experiment — the shared condition manifest (the same panel Tools 2 and 3 embed), so conditions can be assigned before tracking and every tool sees the same per-cell status.
Which linking mode? The trade-off. Strictness costs you data. Measured on the WithER test cell (frames 1–300, 11,535 detections, link 0.8 µm, max-gap 1.4 µm, max gap 1 frame, λ=3, top 6 %):
ModeTracksLinked detectionsMedian lenLongestTracks ≥ 50 frames
Euclidean56011,111 (96.3 %)8.530056
ER-penalty61711,108 (96.3 %)730049
ER-geodesic64410,361 (89.8 %)724637

The strict pre-filter excluded 653 of 11,535 detections (5.7 %) as off their own frame's ER (here no frame was missing an ER mask), and that propagates: tracks surviving the export default of min track length 50 drop from 56 (Euclidean) to 37 (ER-geodesic). ER-penalty excludes no detections at all. Choose geodesic when you need the guarantee that every tracked localization sits on the ER; choose ER-penalty when you want ER-awareness without losing detections.

The whole movie is processed — for the test cell that is 5981 frames (256×256). A player showing "543–5555" is the span of a few random tracks, not the movie length.

2 · Curate & Build

Build turns curated tracks into a TrackStruct whose matrix holds every tracked localization, plus per-track MSD fits. The D fit dropdown chooses how many MSD lags to fit:

  • Fixed % — always fit the first N % of lags.
  • Adaptive R² — per track, use the largest lag-window with R²≥0.95 (linear tracks get more lags, confined/directed ones fewer). Clicking a track adds a sweep of D and R² vs fit-window %.

MSD model: MSD(τ) = 4·D·τ + b. The slope gives the diffusion coefficient D = slope/4; the intercept gives an upper bound on localization precision σ_loc = sqrt(b)/2.

The QC panels beside it are: track length, ER/mito distance, the per-track D distribution, the fit-window sweep — and three stepwise views new. Stepwise D is a different quantity from the MSD fit above: one noise-corrected D at every localization, not one per track, and it is what the confined / state-change flags feed downstream.

  • stepwise D (per localization) — the pooled histogram (log y — the confined peak sits orders below the bulk), with the confined ≤ D threshold drawn on it. Changing that spinner re-derives the flags from the stored D(t); no rebuild.
  • stepwise D(t) — click a track and its D over time appears: mobile localizations in blue, confined in red, and a vertical mark at every state change (a fast→slow entry — a capture event).
  • CSD — cumulative displacement — cumulative path length in µm per track (every track faint, the median bold, the clicked track highlighted). It sums the actual step distances, so a gap-closed step counts its full length.
Named builds new. The Name field next to ▶ Build + QC names the build: it is written to analysis/<name>.mat (e.g. Day1_WT.mat) and recorded in analysis/active_trackstruct.txt as the active build. Several named builds can sit side by side in one analysis/ folder. Everything downstream follows the pointer — a separately launched Analyze tool, the contact-site picker, the window mapper, the footprints and the Experiment tab's "built" lamp all resolve the same way, so they can never disagree about which build a folder is working from. 📂 Load TrackStruct… switches the active build (and shows its QC without recomputing MSD). Leave the name at TrackStruct and nothing changes: a project with no pointer falls back to TrackStruct.mat.

3 · Analyze

The analysis tool has six tabs — Contact sites · Refine · Sites · Dwell · Experiment · Compare. It starts from the active build; there is no separate density stage, the density is built inside the Contact-sites tab. The heart of it — Contact sites — is where density peaks become candidate sites, so most of this guide's deep dives live there.

Spot detection (Tool 1)

Detection is a band-pass blob finder, not a Gaussian fit:

  1. DoG band-pass (spt_dog) — difference of Gaussians tuned to the spot diameter, which suppresses both shot noise (small scale) and uneven background (large scale).
  2. Threshold — keep pixels above the top-percentile (or absolute quality) cut.
  3. 5×5 non-max suppression — one peak per local maximum.
  4. Intensity-weighted centroid — sub-pixel position (no fitted σ, so no CRLB precision — use the MSD-intercept σ_loc instead).

Each spot also carries an elongation (2nd-moment ratio): round spots ≈ 1.0, motion-blurred streaks ≳ 1.5. In the Detect preview, red rings flag elong ≥ 1.5 — a quick motion-blur check.

Density & counts (tracked-only)

A contact site is a place where the protein concentrates, so everything downstream is built on a localization-density map. Two rules matter:

The density is always built from TRACKED localizations — spots that belong to a track. Single-frame detections (noise, blinks) are excluded. For WithER: 101,948 tracked localizations out of 220,401 total detections — so 54 % of the raw cloud was noise that never enters the density.

The picker always shows all three counts so you know what you're looking at:

detections 220401 · tracked 101948 (46%, density source) · 4 windows · THIS window 27172 tracked locs

and every window thumbnail shows its own count, turning red ⚠ if it falls below the min locs/win floor.

The density map, in code

% bin tracked localizations (µm) whose frame is in [t0,t1] onto the grid, then Gaussian-smooth
Lx = round(X/SF);  Ly = round(Y/SF);            % µm → density pixel  (SF = FOV/grid)
counts = accumarray([Ly Lx], 1, [H W]);          % row = y, col = x
dens   = imgaussfilt(counts, 8);                 % σ = 8 px detection scale

Windowing — and "how many localizations is enough"

Contact sites move and turn over, so the density is built per time window, not over the whole movie. Controls on the Contact-sites tab:

ControlWhat it does
frames/winWindow length. ceil(nFrames/this) non-overlapping windows.
step framesStart stride. 0 (or ≥ frames/win) = back-to-back. Smaller = overlapping windows that track a moving site more smoothly (more panels; not statistically independent).
min locs/winA warning floor only — flags under-powered windows red. Changes nothing else.
⇢ Sweep window lengthRe-runs detection at several window lengths and plots # sites + median significance vs window length, so you can pick the knee.
The trade-off. Shorter windows = better temporal detail but fewer localizations each (noisier density). Longer = more localizations (robust) but a moving site smears.

Rough floors per window: <300 too noisy · 1–2k minimum · 5k+ confident · whole-movie best (static sites only).

Find your minimum with the sweep: read it right-to-left (dense → sparse); your minimum is the loc/win at the last point before # sites drops or significance falls below ~0.9. For WithER the sweep is flat (16–23 sites, significance ≈ 1.0 down to ~6,800 loc/win) — that cell is not localization-limited, so window length is chosen by how fast the sites move, not by count.

The Monte-Carlo null & significance

How do we know a bright patch is a real site and not a random clump? We compare it to a null: if the same number of localizations were scattered at random over the ER, how bright would the brightest chance-peak be?

% cs_mc_threshold: M random realizations, keep only each run's PEAK smoothed density
for m = 1:M
    sel = randOnMask(N);                     % scatter N points over the ER mask
    Dm  = imgaussfilt(accumarray(sel,1), 8); % smooth the SAME way as the data
    nullMax(m) = max(Dm(mask));              % the brightest chance-peak this run
end
Dthr = quantile(nullMax, 1-alpha);           % detection cutoff (family-wise error ≈ alpha)
Why it's fast. The whole null is just M numbers (the peak maxima). A site's significance is then a lookup, not a new simulation: 
p = mean(nullMax >= siteDensity);   % fraction of chance-peaks at least as bright
Keeping only the max of each run builds the multiple-comparison (family-wise) correction in for free — one null covers every pixel at once. With M runs the finest resolvable p is 1/M (so 80 runs can't distinguish anything stronger than p ≈ 0.012).

The colorbar shows this null band + the cutoff; the "significance (p)" display recolours the map by per-pixel p.

Robust peak detection upgraded

The base detector thresholds the smoothed density, drops specks, and takes one centroid per blob. Several upgrades make it more trustworthy. All are on the Contact-sites tab; re-run Detect to apply.

Split merged peaks

Two real peaks that touch above the threshold used to collapse into a single centroid at the saddle. split peaks (on by default) runs a marker-controlled watershed so each prominent maximum becomes its own site.

mk = imregionalmax(imhmax(dens, h)) & bw;    % markers = peaks standing ≥ h above surroundings
I  = imimposemin(-dens, mk);                 % basins only at the markers
L  = watershed(I);                           % → one label per genuine peak

Effect-size gate — min enrich ×

A peak can be statistically significant yet trivially small. Require its peak density to be at least this multiple of the ER-median background. 1× = off. Concretely, on WithER a gate of 7× keeps 6 of 28 sites (enrichment 7–11×).

Distinct-molecule gate — min tracks SPT-specific

The subtle one. Density counts localizations, but one molecule parked at a spot for 500 frames dumps ~500 near-identical points and looks exactly like a busy site. This gate keeps a site only if at least this many distinct track IDs contribute — a real contact site is visited by many molecules. On WithER, requiring ≥16 distinct tracks cut 28 candidate sites to 13 (several had only 2–6 tracks).

Stability score

Each detected site gets a stab value (0–1): the fraction of random split-halves of the data in which the site's peak stays enriched in both halves. A real site scores 1.0; a one-off blip scores low. It's shown in the per-site table (no gating — you decide).

The radial (cell-wide ER) null

On the Refine tab, the radial plot asks whether a site's localizations concentrate toward its centre more than expected. The dashed "uniform" line is not a disk of local density — it is what you'd see if these localizations were spread uniformly over all the cell's ER at the average density:

ρ    = (localizations over ER, whole cell) / (total cell ER area);
ref(r) = ρ · A_ER(r);        % A_ER(r) = ER area within radius r of the site centre

So the observed curve sitting far above the dashed line means genuine enrichment above the cell's ER background — not just "there's ER here." On the busiest WithER site the null is ≈9 localizations within 1.2 µm versus 670 observed (≈75× enrichment).

Dwell & escape rate

Once sites are mapped, the Dwell tab measures how long each member track resides inside a site's footprint (clipped to that site's own window). A dwell event is a maximal run of consecutive inside-footprint localizations; duration = span·dt. Per window it reports the escape rate k_out = nEvents / Σdwell. The per-track table is keyed by cell · site · window · track so every row is traceable back to a specific molecule at a specific site.

Transparency & provenance new

Every number the detector uses is visible, and every saved result records how it was made.

  • Per-site stats table (right of the Contact-sites map): each site's p, enrichment ×, distinct trk, enclosed loc, and stab. Click a row to highlight it on the map.
  • 🔍 explain spot: turn it on and click anywhere on the density — even a place with no detected site — to read that point's density, null percentile, enrichment, #tracks and p. Use it to understand near-misses ("why wasn't this called a site?").
  • Tracking settings file: every Tool 1 run writes tracks/<base>_settings.txt with the detection + linking parameters actually used. It records the effective linking mode, and adds tracking.link_mode_req only when an ER mode had to be downgraded (no ER segmentation for that cell). In ER-geodesic it also reports tracking.frames_no_er_mask (frames whose missing ER mask contributed nothing) and tracking.dets_off_er (detections excluded as off their own frame's ER).
  • Provenance stamp: Save writes, next to the sites, a _CSsites_provenance.json with the exact parameters (method, α, M, σ, gates, source, window ranges, date) and a _CSsites_stats.csv with every site's stats — so a result is fully reproducible.

Recipes & FAQ

"How do I choose the window length?"

Run ⇢ Sweep window length. Pick the shortest window where # sites has plateaued and significance is still high. If your sites are static, longer windows give the most power; if they move, go shorter and accept a few fewer.

"A bright spot wasn't detected — why?"

Turn on 🔍 explain spot and click it. You'll see its p (maybe it didn't clear the null), its enrichment (maybe below min enrich), or its #tracks (maybe one parked molecule below min tracks).

"My density looks different after an update."

The density is now tracked-only (single-frame noise excluded) and defaults changed — re-pick sites; the density source is locked per pick, so old picks keep their old source until you re-pick.

"MATLAB says a callback errored after I edited an app file."

Close and relaunch the app — MATLAB apps don't hot-reload, so a stale figure can throw phantom callback errors.
